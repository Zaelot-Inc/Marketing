## Summary

The session opened with an audience poll about reliance on software, followed by a pitch built around industry statistics: roughly 58% of engineering time is spent understanding existing systems and code, and while AI tools let engineers produce code about 25 times faster, 96% of teams are not confident that AI-generated code is correct, leading to more bugs per developer and review times five times longer. The net result, it was argued, is that AI coding tools alone only yield about 30% productivity gain once these costs are factored in.

Travel was framed as especially exposed to this risk because, after building software for travel clients since 2009, the speaker described typical travel infrastructure as a hybrid of 20-year-old legacy systems and newer, partly AI-generated code, all handling billions of dollars in transactions and customer data — described as a 'ticking bomb with a high blast radius.'

The proposed solution, Interlace, was presented as a product built by travel-tech engineers rather than a generic product team, designed to map an entire software stack into a multidimensional graph of components, user flows, endpoints, and underlying business logic. It acts as a context layer connecting engineers or AI agents to existing coding tools (Cursor, Claude, Codex, etc.), letting users ask in plain language what would happen if a system change were made, with Interlace identifying all impacted systems and logic changes — intended to help even when a senior developer or an entire engineering firm is gone.

Claimed benefits included shipping speed increasing 35% versus using AI coding tools alone, roughly 25% savings on token spend, and a worked example where a $6 million modernization budget could generate $8 million in value plus $60K in token savings. The system was described as deployed within the customer's own cloud with zero code access for AltexSoft and ISO certification, targeting the roughly 700 largest global travel businesses in a $60 billion addressable market, and positioned against proprietary systems like one Uber was said to have built in-house, offering a comparable solution in as little as two weeks.

Audience feedback was mixed, with mostly positive reactions but some skepticism. Questions probed whether the claimed ROI came from token savings or labor savings, with the response pointing to productivity gains from paying clients, including one in attendance, as the primary driver. Another questioner argued that software engineering as a target is becoming obsolete as AI takes over more tasks, and asked whether Interlace was aimed at companies lacking strong prompt engineering skills; the response countered that context behind large, complex systems is the real challenge that good prompting alone cannot solve, and claimed Interlace outperforms roughly ten competing products that have each raised between $10 and $120 million. A further critique raised doubts about how the value was measured and suggested a mismatch between which companies need the product and which are enthusiastic about it, closing the session on a note of unresolved skepticism.

AltexSoft positions Interlace as a quickly deployable alternative to building an equivalent internal system, citing a two-week leasing timeline and Uber’s reported investment in a similar proprietary capability.

> Uber... announced they built the very same proprietary system. We don't know how many millions of dollars and months of software engineering work they put in. But you can get Interlace with us in as much as 2 weeks.

The speaker claims Interlace increases real shipping speed by 35% compared with AI coding tools alone and reduces token spending by at least 25%. A cited example describes a $6 million modernization budget producing $8 million in annual value, with token savings as an additional benefit.

Quotes:

> We see that real shipping speed is actually going up 35% compared to using AI coding tools alone... with Interlace we see at least 25% savings with the token spend.

### 🧩 Interlace maps the software stack as a multidimensional graph

AltexSoft's Interlace is presented as a system that maps an entire software stack into a connected, multidimensional graph of components, user flows, and endpoints.

Quotes:

> Interlace maps out your entire software stack into multi-dimensional graph. You understand the components user flows endpoints.

The discussion raised doubts about how productivity gains are measured and whether the organizations that most need system-understanding support will recognize or accept that need. The speaker responded that complexity and lack of context—not prompting skill alone—are the core problem.

### 🔍 Faster AI-generated code creates a verification burden

The speaker says engineers are producing code roughly 25 times faster with current AI tools, while 96% remain uncertain whether the output is correct—creating a substantial need for review and validation.

Quotes:

> Nowadays the engineers on average code 25 times faster... however 96% are not sure what has been produced is correct.

### 👥 System knowledge should survive team turnover

The proposed use case addresses the loss of institutional knowledge when senior developers leave or an external development firm is replaced. The system is intended to help users understand and modify the software despite that turnover.

Quotes:

> Imagine a use case when your senior developer is gone or you fire the whole firm which has been building your software.

### 🧠 The product is designed to trace business logic

Beyond cataloging technical components, Interlace is intended to reliably trace the business logic behind them—an important capability when systems outlive the teams that built them.

Quotes:

> What is the most important thing... it reliably traces the business logic behind it.

### 💥 Hybrid travel infrastructure creates a potentially large blast radius

Travel businesses may run decades-old software alongside newer and partially AI-generated components, all handling billions of dollars in transactions and customer data. Poorly understood changes in such systems can therefore have wide consequences.

Quotes:

> The common software infrastructure is kind of like a hybrid. It could be a hybrid of 20-year-old software which you either acquired or built and something very new, very modern, partially generated by AI... This is all at risk because it's a ticking bomb with a high blast radius.

### 🔐 Interlace is deployed in the customer’s cloud without code access

The product is presented as a security-conscious deployment: it runs in the customer’s cloud, AltexSoft claims to have zero access to the customer’s code, and the product is ISO certified.

Quotes:

> We deploy in your cloud, AltexSoft has zero access to your code and it's ISO certified.
